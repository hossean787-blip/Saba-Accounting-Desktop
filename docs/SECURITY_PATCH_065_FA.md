# نسخه توسعه‌ای ۰.۶.۵ — اصلاحات امنیت و دسترسی

مبنای تغییر: نسخه ۰.۶.۴؛ مستقل از سایر پروژه‌ها.

## تغییرات اجراشده
1. پس از تعریف نخستین کاربر نام‌دار، ورود با گذرواژه مشترک قدیمی (`local_login`) غیرفعال می‌شود. مسیر سابق قبلاً می‌توانست نقش‌های کاربران را دور بزند. هیچ گذرواژه‌ای حذف نشده و اطلاعات مالی تغییر نمی‌کند.
2. تغییر گذرواژه مشترک با ابزار قدیمی در حالت چندکاربره نیز مسدود شد؛ تغییر رمز حساب‌ها باید از مدیریت کاربران انجام شود.
3. نمای بیرونی مجوزدار `AuthorizedStore` دیگر روش‌های خصوصی ذخیره‌ساز را از `__getattr__` عبور نمی‌دهد. دقت: دسترسی مستقیم به فایل SQLite توسط عامل دارای مجوز سیستم‌عامل هنوز محافظت نمی‌شود؛ کنترل نقش صرفاً مرز برنامه است.
4. انتخابگرهای کارمند، دارایی و پروژه در UI به‌جای اتصال مستقیم به SQLite، از سرویس عمومی `reference_choices` با محدودسازی شرکت و نوع جدول استفاده می‌کنند.
5. چند آزمون قدیمی با `with sqlite3.connect(...)` (که اتصال را نمی‌بندد) به `contextlib.closing` تغییر داده شدند.

## آزمون
- در محیط Linux، `python -m unittest discover -s tests -q` => ۱۸۰ آزمون، همه موفق.
- `python -m compileall -q main.py saba_accounting tests` => موفق.
- هنوز دست‌کم یک ResourceWarning اتصال SQLite در اجرای کامل دیده شد؛ بنابراین رفع کامل هشدار ادعا نمی‌شود.
- EXE ویندوز در این محیط ساخته یا روی ویندوز اجرا نشده است.

## محدودیت‌های انتشار
رمزگذاری داده در حالت سکون، امنیت فایل SQLite در برابر کاربران سیستم‌عامل، تکمیل کنترل دسترسی در همه مسیرها، آزمون خودکار Windows و پذیرش حسابداری واقعی هنوز الزامی‌اند. این بسته نسخه توسعه‌ای است نه محصول تجاری.
